-------What is an API ?
Application Programming Interface (API) is a bridge through which two software systems communicates.
Frontend --> API --> Backend --> Database
(frontend and backend are software systems)
(network join the frontend and backend and through API they talk)

An API (Application Programming Interface) is a defined way for one piece of software to ask another piece of software to do something or give it data, without needing to know how the other side works internally. Think of a restaurant: you (the client) don’t walk into the kitchen. You give your order to a waiter (the API), who relays it to the kitchen (the server) and brings back your food (the response).

---------Client vs server
Client: the program that initiates a request. It could be a mobile app, a browser, a Python script, or an AI agent.
Server: the program that listens for requests, does the work (reads a database, runs logic, calls a model), and sends back a result.

---------EndPoints
(An API endpoint is simply a URL that represents a specific resource or functionality in an API. Think of it as a address you are sending to a server without it the API has nowhere to go)
An endpoint is a specific URL where the server exposes one capability. A base URL plus a path identifies what you’re asking for:

https://api.example.com/v1/users/42
https://api.example.com is the base URL
/v1 is often the API version
/users/42 is the resource (user number 42)
Different endpoints do different things: /users might list users, /users/42 fetches one, /orders handles orders.


------Requests
A request is the message the client sends. It has:

Method: what action you want. The common HTTP methods are:
GET to read data
POST to create something
PUT/PATCH to update
DELETE to remove
URL: the endpoint, optionally with query parameters (?limit=10&sort=name)
Headers: metadata such as authentication (Authorization: Bearer <key>) and content type (Content-Type: application/json)
Body: the data you’re sending (mainly for POST/PUT/PATCH), usually JSON


------Responses
A response is what the server sends back. It has:

Status code: a number summarizing the outcome
2xx success (200 OK, 201 Created)
4xx client error (400 Bad Request, 401 Unauthorized, 404 Not Found, 429 Too Many Requests)
5xx server error (500 Internal Server Error)
Headers: metadata about the response
Body: the actual data, typically JSON


-----HTTPS methods:
The common HTTP methods are:
GET to read data
POST to create something
PUT/PATCH to update
DELETE to remove


-----example
import requests
response = requests.get(
    "https://api.example.com/v1/users/42",
    headers={"Authorization": "Bearer YOUR_KEY"},
    params={"include": "profile"},
)

print(response.status_code)   # 200
print(response.json())        # {"id": 42, "name": "Ada", ...}


------- Status Codes
The status code is a three-digit number in every response summarizing what happened. The first digit tells you the category.
Range	Meaning	        Who’s at fault?
1xx	    Informational	Rarely seen
2xx	    Success	        n/a
3xx	    Redirection	    n/a
4xx	    Client error	You (the caller)
5xx	    Server error	The server
-----example
import requests
r = requests.get("https://api.example.com/v1/users/42")
if r.status_code == 200:
   print(r.json())
elif r.status_code == 404:
   print("User not found")
else
   r.raise_for_status()   # raises an exception for any 4xx/5xx
